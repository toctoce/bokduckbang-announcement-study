## 실행과 배포

Node 24.19.0 / npm 11.17.0에서 `frontend` 디렉터리로 이동한다.

```sh
npm ci
npm run dev
npm run check
npm run generate:study
```

Vercel의 Root Directory는 `frontend`, Framework는 Vite, Build는 `npm run build`, Output은 `dist`, Node는 24.x로 설정한다. 환경변수는 아래 두 개만 필요하다. 브라우저 공개 설정이며 비밀 서버 키는 사용하지 않는다.

- `VITE_NAVER_MAPS_CLIENT_ID`: NAVER Maps JavaScript SDK client ID. Naver Cloud의 Web 서비스 URL에 배포 도메인과 localhost를 등록한다.
- `VITE_TALLY_FORM_ID=jadN9a`: Tally 설문 ID.

실험 진입점은 `src/experiment/main.tsx`, 빌드 설정은 `vite.study.config.ts`다. 기존 운영 App과 개발용 스냅샷 로더는 보존한다. 운영 API·로그인·알림·거리뷰·운영 GA/PostHog를 초기화하지 않는다. 지역 경계 파일과 예시 JSON은 정적 파일로 요청한다. 공개 검색엔진에는 noindex로 표시한다.

## 데이터

`npm run generate:study`가 지역 자료와 작성 규칙으로 `public/study/national-500-v2.json`을 재생성한다. 500개 단지/30개 공고, 서울250/경기인천80/강원20/충청40/호남40/영남60/제주10, 공고중10/접수중16/마감4다. 기준일은 2026-10-14로 고정한다.

진행 중 공고와 연결된 단지는 총 34개다. 구성된 55개 시·군·구 중 35곳은 0개, 12곳은 1개, 5곳은 2개이며 3·4·5개인 지역은 각각 1곳이다. 모든 권역에 진행 중 공고가 있고, 공고가 없는 지역은 공고지도에 핀을 표시하지 않는다.

단지 이름·위치·모집조건은 합성 예시이며 실제 모집공고가 아니다. 기존 지역 대표점을 기준으로 구역 경계 안에 가상 위치를 분산한다. 읍면동 코드는 실험용 분류이며 실제 필지 주소를 뜻하지 않는다. 공개 서비스의 화면과 정보 구조를 참고했다. 운영 데이터를 복제하거나 운영 API에 의존하지 않는다.

지도는 동일한 조회 범위와 필터를 통과한 단지를 9/11/13 배율 경계로 집계한다. 지역 핀 숫자는 현재 조회 범위의 단지 수이며, 공고지도에서는 진행 중 공고가 하나 이상인 단지 수다. 복수 공고는 한 단지로 센다. 경계 밖 단지가 확대 후 추가로 들어오면 화면 전체 숫자는 달라질 수 있다. 테스트는 동일한 범위·조건에서 집계 합계와 개별 핀 수를 비교한다.

## 실험과 측정

첫 진입에는 설문 전 서비스 소개를 한다는 짧은 안내를 보여 준다. 소개 후 검색·필터·목록·최근 본 단지·확대/축소 버튼을 하나씩 눌러 확인하도록 권한다. 완료를 강제하지 않으며, 준비됐어요·설문 시작하기를 누르면 단지의 위치를 보는 기능과 현재 모집공고가 열린 단지를 찾는 과제의 차이를 설명한다. 서비스·버튼 소개는 단계 수에 포함하지 않는다. 본 체험은 **① 첫 번째 방법 → ② 두 번째 방법 → ③ 비교·설문**이다. 새 세션마다 `crypto.getRandomValues`로 필터/공고지도 순서를 50% 확률로 배정하고 sessionStorage에 저장한다. 정확히 절반씩 배정하지는 않는다.

두 방법은 서울 중심(37.5665,126.978), 배율11, 필터/상세 초기화 상태에서 시작한다. 메뉴는 PC 왼쪽, 모바일 하단에 있다. 필터 체험 동안 공고지도 메뉴를 숨기고 공고지도 체험과 비교 화면에서 표시한다. 서비스 소개는 단지지도·검색·모집상태·공급기관 필터·공고 목록·최근 본 단지·지도 확대를 설명한다. 필터는 역할만 설명하고 자동 적용하지 않는다. 공고 탭 소개에서는 실제 목록을 열며 패널 전환 후에도 강조 위치를 갱신한다. 버튼 둘러보기 진입 시 필터·목록을 초기화한다. 공고 핀은 단지 핀과 비슷한 말풍선 형태에 기관·상태, 두 줄 공고명과 접수 시작~종료일을 보여 준다.

시작 모달 제목은 방법 이름(필터로 찾기/공고지도로 찾기)만 표시하며 동일한 과제와 짧은 조작 순서를 안내한다. 체험 중에는 위치를 강조하거나 안내를 자동으로 띄우지 않는다. 직접 사용하는 시간이 15초 쌓이면 힌트 보기 하나가 활성화된다. 힌트는 필터·지도 확대 수준·목록·실제 단지 상세의 진행 중 공고 유무에 맞는 행동 문장만 보여 준다. 공고 없는 단지에서는 다른 단지를 찾도록 안내한다. 비활성화 중에는 카운트다운 문구가 없고, 활성화되면 버튼 색과 테두리로 강조한다. 건너뛰기 버튼 없이 해당 방법의 경로로 완료하면 같은 단계에서 찾기 쉬웠던 정도 1~5점 또는 판단하기 어려워요를 선택한다. 선택 즉시 다음 단계로 이동한다. 완료 후 사용법을 반복하지 않는다.

필터 체험은 진행 중 모집상태 조건으로 선택한 단지지도 핀에서 연결 공고를 열었을 때, 공고지도 체험은 공고 요약 핀에서 열었을 때만 완료한다. 복수 공고 선택도 인정한다. 상세 요청 ID·공고 ID·연결 단지·진입 경로·핀 선택 당시 모집상태를 실제 상세 표시와 연결한다. 탭 방문 이력이나 검색·공고 목록·다른 방법으로 연 상세는 완료 근거가 아니다. 마감 공고와 이전 요청의 늦은 응답도 제외한다.

지도와 데이터가 준비되고 탭이 보이는 직접 체험 시간만 누적한다. 서비스 소개·자유 탐색·비교 목적 안내·방법 시작 모달·힌트 읽기·직후 평가·백그라운드 시간은 제외한다. 새로고침은 순서와 평가를 복원하고 진행 중 과제만 interrupted로 구분하며 이전 상세 요청을 폐기한다. 비교 단계의 재탐색은 최초 기록과 평가를 덮어쓰지 않는다. 오류와 재시도는 별도로 남긴다.

같은 세션으로 재제출할 수 있으므로 분석에서 `session_id`를 중복 제거한다. `?test=1`로 시작한 새 탭은 테스트 기록이며 분석에서 제외한다. 이미 진행 중인 탭의 테스트 여부는 저장된 상태를 유지한다. 새 탭에서 시작해야 새 참여번호가 생성된다.

## 설문 계약과 교체

`ExperimentSummary`는 지도·체험과 독립적인 공통 계약이다. `tallyAdapter.ts`만 Tally 숨김 필드 이름을 안다. 질문 버전 `survey-v3`, 실험 버전 `announcement-map-v8`, 데이터 버전 `national-500-v2`를 고정한다. v8은 붉은 테두리로 기능을 강조하고 핀 색상(주황 공고중·파랑 접수중·회색 진행 중 공고 없음·초록 선택한 단지)을 설명하고 실제 단지 상세 → 공고 상세와 공고 목록 → 공고 상세를 보여 준다. 필터는 자동 적용하지 않으며 버튼 둘러보기 후 필터 → 공고지도 순서로 체험한다. 공고지도 과제를 다른 경로로 열면 공고지도 버튼을 강조하며 모바일 상세도 메뉴를 가리지 않게 표시한다. 15초 뒤 요청형 상황 힌트와 직후 평가를 제공하며 중간 마치기 버튼은 없다. 마지막 직후 평가를 선택하면 중간 카드 없이 설문이 바로 열린다. 지도로 돌아가 재탐색할 수 있으며 기존 기록은 유지한다. v7와 체험 순서와 선택 이유 문항이 달라 별도 버전으로 집계한다. 이전 버전 세션은 처음부터 시작하며 이전 응답과 합산하지 않는다.

공통 질문 ID: `interest`, `ease_old`, `ease_new`, `preference`, `need`, `reasons`, `reason_text`, `comment`. Tally 편집 화면의 실제 블록 ID와 이 공통 ID는 다른 개념이다. Tally 질문 제목은 시트 분석 계약이므로 문구를 바꾸면 분석 매핑도 수정한다.

숨김 필드(34개): `experiment_version`, `question_version`, `dataset_version`, `as_of`, `session_id`, `screen`, `is_test`, `method_order`와 old/new 각각 `outcome`, `success`, `unaided`, `help`, `help_reason`, `elapsed_ms`, `help_at_ms`, `paths`, `interrupted`, `errors`, `retries`, `completion_source`, 그리고 `ease_old`, `ease_new`다. `old`는 필터, `new`는 공고지도라는 고정 방법 ID이며 진행 순서가 아니다. method_order는 old,new, ease는 1~5 또는 unsure, completion_source는 filtered_complex/announcement_pin 또는 건너뜀의 빈 값이다. unaided는 이전 계약 호환용이며 기능 발견률로 해석하지 않는다.

기존 난이도 문항은 숨겨 과거 응답을 보존하고 직후 평가를 숨김 필드로 전달한다. 기존 필요성 선형 척도도 숨겨 보존하고, survey-v2는 판단 보류가 있는 선택형 문항을 사용한다. survey-v3에서는 이전 선호 문항도 숨겨 응답을 보존하며, “두 방법 중 어떤 방식을 더 선호하나요?”에 필터로 찾기 (첫 번째 방법) / 공고지도로 찾기 (두 번째 방법)을 표시한다. 선택 이유에 “어디를 눌러야 할지 바로 알 수 있어서”와 선택 작성 주관식 문항을 추가한다. 마지막 설문에는 관심도, 선호, 필터가 있어도 별도 공고지도 탭이 필요한지, 긍정·부정 선택 이유, 선택 의견만 남긴다. 필요성은 1~5와 판단하기 어려움을 제공한다.

iframe의 origin, source, formId를 확인한 Tally.FormSubmitted 이벤트만 완료로 인정한다. 새 창 대체 링크는 같은 필드를 전달하지만 외부 창의 완료는 원래 페이지에서 확인하지 못하므로 외부 설문의 완료 화면을 따른다. 15초 내 FormLoaded 이벤트가 없으면 대체 링크 안내를 표시한다. Tally 제출과 Google Sheets 동기화는 별도 검증한다.

Supabase로 바꿀 때 자체 설문 화면과 저장 endpoint/권한 정책을 추가하고 TallySurvey 어댑터를 교체한다. 지도와 체험 모듈은 유지한다. 기존 CSV는 공통 질문 ID와 ExperimentSummary 항목으로 변환해 이전한다.

## 파일럿과 결과 해석

1. 테스트 세션에서 PC·모바일 각각 기존 필터, 공고지도 핀, 복수 공고, 마감 공고, 새로고침, 네트워크 오류, 설문 제출을 확인한다.
2. 시트에서 동일 session_id에 질문 응답과 old/new 기록이 함께 들어왔는지 확인한다.
3. 공공주택 관심자 5명으로 파일럿한다. 중간에 UI·안내·데이터를 바꾸면 버전을 올린다.
4. 수정한 동일 버전으로 유효 응답 30개를 모은다. 테스트·중복·체험정보가 없는 직접 설문 응답은 분석에서 제외한다. 중단/오류 기록은 따로 집계하고 정상 소요시간 중앙값에서는 제외한다.
5. 핵심 지표는 방법별 선호 비율, 필요성 4~5점 비율과 평균, 직후 난이도, 선택 이유다. 지정 경로 완료율·추가 도움 사용률·완료자의 정상 소요시간 중앙값은 참고 지표다. 전체와 고정 체험 순서의 결과, 모두 완료/건너뜀 포함 결과를 함께 확인한다. 판단하기 어려움도 비율 분모에 포함하고 평균에서만 제외한다.

고정 순서의 학습 효과가 포함될 수 있다. 공고지도 선호60% 이상, 필요성4~5점60% 이상을 후속 도입 검토 기준으로 사용한다. 도움 없이 기능을 발견한 비율이나 실제 사용량 증가의 증거로 해석하지 않는다. 건너뛴 응답은 자동 제외하지 않는다. 제출 전 이탈자는 수집하지 않으며 실제 참여자 모집과 5명 파일럿·유효 응답 30개 수집은 별도로 진행한다.

## Google Sheets 자동 요약

Tally는 `시트1`에 원본을 저장하고, `분석 요약`은 첫 500개 응답을 자동 계산한다. 원본 탭과 이전 응답은 보존한다. 요약은 열 제목으로 새 메타데이터를 연결한다. 테스트·중복·버전 불일치 응답을 제외하며, 70행부터 시작하는 계산표 V열에서 선택 이유, W열에서 의견, Z열에서 직접 작성한 선택 이유를 볼 수 있다. 500개를 넘으면 요약에 범위 확장 안내가 표시된다. 유효 응답이 없으면 비율·중앙값은 “응답 없음”으로 표시한다.

## CSV 재현 분석

Tally 또는 연결된 Google Sheets의 원본 CSV를 내려받아 `npm run analyze:study -- /path/to/export.csv`로 분석할 수 있다. 응답은 외부로 전송하지 않는다. Tally의 소문자 불리언과 Google Sheets의 대문자 TRUE/FALSE 내보내기를 모두 지원한다. 같은 session_id의 첫 유효 응답만 사용하고, 테스트·다른 버전·불완전한 기록은 제외한다. 체험 순서·완료 여부별 핵심 지표와 지정 경로 완료율·추가 도움 사용률·완료자의 소요시간 중앙값을 계산한다. 중단·오류·재시도 기록은 정상 측정에서 제외한 개수를 함께 표시한다. 표본이 없으면 0이 아닌 null을 반환한다. 원본 응답 파일은 저장소에 커밋하지 않는다.
