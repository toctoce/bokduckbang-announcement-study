# PDF 근거로 데이터 보완

## 관리자 흐름

1. 단지·공고 상세의 `PDF로 보완`에서 기본정보·주택형·공급행·임대조건을 선택한다.
2. 공식 출처 URL과 PDF를 선택하고 필요한 쪽수(예: `1-3, 7`)만 추출한다.
3. 원문과 추출 텍스트를 비교하고 `에이전트 자료 다운로드`의 JSON을 에이전트에 전달한다.
4. 에이전트 응답 JSON을 가져오거나, 페이지 인용과 변경 이유를 넣어 수기 수정안을 추가한다.
5. 현재값·수정안·단위·적용 범위·인용을 확인한 항목만 선택하고 확인 메모를 작성한다.
6. 반영 후 `출처·수정 이력`에서 변경값과 문서 근거를 조회한다.

주소는 PNU·행정구역·좌표를 함께 확인해 기존 주소 편집으로 수정한다.
이미 검토된 접수 기간은 기존 접수 일정 편집에서 수정한다.
이 화면의 수정은 단지 전체를 검증 완료로 표시하지 않는다. 실제 확인한 범위는 기존 검증 화면에 기록한다.
임대조건은 조회 당시 값과 현재 값을 함께 비교한다. 수집 중 값이 바뀌면 저장을 중단하고 수정안을 유지한다.
검토 결과를 내려받아 보관한 뒤 `현재 데이터 다시 조회`로 최신 값을 확인하고 다시 검토한다.

## 에이전트 응답

자료의 `responseTemplate`과 `allowedFields`를 기준으로 다음 응답을 반환한다.

```json
{
  "schemaVersion": "document-review/v1",
  "targetKey": "complexes:7:basic",
  "version": 2,
  "sha256": "다운로드 자료의 64자리 해시",
  "proposals": [{
    "field": "totalHouseholdCount", "value": 120, "page": 2,
    "quote": "단지 전체 세대수 120세대", "unit": "세대",
    "scope": "단지 전체", "reason": "전체 세대수 보완"
  }],
  "unresolved": [{"field": "completionDate", "reason": "선택한 페이지에 없음"}]
}
```

금액은 원 단위의 18자리 이하 정수 **문자열**이다. 예: `"12000000"`.
기관·유형은 자료에 나열된 enum, 날짜는 실제 존재하는 `YYYY-MM-DD`로 반환한다.
미확인 값을 0으로 채우거나 세대수를 임의로 합산하지 않는다. 같은 항목의 중복·미확정 제안은 거부한다.

## 처리 한계와 비용

- 유료 AI API와 자동 외부 전송을 사용하지 않는다. 운영자가 다운로드한 자료를 직접 전달한다.
- PDF.js는 선택 페이지의 텍스트와 위치를 추출한다. 표의 병합 셀·행/열 구조를 확정하지 않는다.
- 25MB·10,000쪽 이하 파일, 한 번에 50쪽·500,000자 이하를 처리한다. 같은 세션의 페이지는 재사용한다.
- 텍스트 없는 페이지는 `OCR 필요`다. OCR 처리된 PDF로 다시 작업하거나 기존 수기 편집을 사용한다.
- 해시·대상·버전·항목 형식·단위·범위·인용을 브라우저에서 검사한다. 값이 인용의 의미와 맞는지는 사람이 확인한다.
- 서버는 관리자 권한·CSRF·버전·근거 형식을 검증한다. PDF 원문을 내려받아 재검증하거나 원본 파일을 보관하지 않는다.
- 페이지 캐시는 메모리에만 있다. 새로고침 전에 필요한 자료·결과를 다운로드한다.

## 단지 누락 대조

관리자 메뉴 `단지 누락 대조`에 공식 출처 URL·기준일·기관과 단지명·도로명주소의 JSON 목록(최대 50개)을 넣는다.
서비스와 같은 원천 식별자만 선택적으로 `sourceIdentifier`에 넣는다.
기관별 이름·주소 검색과 휴지통 검색을 수행하고 등록 확인·미등록 후보·동일성 검토·휴지통 후보·조회 실패로 나눈다.
검색 상한이나 실패는 미등록으로 판단하지 않는다. 결과를 내려받고 수집 실패·다른 명칭·공개 노출 조건을 직접 확인한다.
후보의 자동 등록·연결·복구는 수행하지 않는다.

- 브라우저의 API 응답은 격리된 검증 자료를 사용했다. 실제 기관 공고 전체 유형·운영 재수집·배포는 검증하지 않았다.
